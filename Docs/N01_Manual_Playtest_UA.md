# N01 — ручна перевірка pickup і старих взаємодій

Мета: переконатися, що звичайне підняття, кидання й передача предметів працюють як раніше, а два гравці більше не можуть привласнити один предмет звичайним pickup.

**Єдина очікувана зміна:** другий pickup уже зайнятого предмета відхиляється. Предмет переходить іншому гравцеві після нормального drop або через спеціальну передачу, зокрема дзеркало.

## Підготовка

1. Перезапусти Unreal Editor після збірки N01. Якщо тестуєш `.exe`, спочатку зроби нову збірку гри: успішна збірка Editor сама не оновлює старий packaged `.exe`.
2. Запусти хост і одного клієнта. Для швидких перевірок підійдуть два ігрові вікна; для одночасного натискання потрібні двоє людей із незалежним керуванням, найзручніше — два ПК. Почни без штучної затримки мережі.
3. Познач гравців **А** та **Б**. Підготуй два звичайні предмети, які можна тримати: **П1** і **П2**. Годинник, стілець, HotDot або вже встановлена руна для базового pickup-тесту не підходять.
4. Для тесту конкуренції обидва гравці повинні мати право підняти **той самий actor П1**. Найпростіше — предмет з `ItemTimeline=Both`. За потреби підготуй два звичайні pickup-предмети з Both на **копії** DemoMap1. Не змінюй основну мапу заради цього тесту.
5. До початку конкуренції окремо перевір: А піднімає П1 і кидає, потім Б піднімає саме цей П1 і кидає. Два схожих предмети в Past/Future — це не один спільний предмет. Якщо будь-хто не може підняти його навіть наодинці, спочатку перевір доступність/timeline; тест конкуренції ще не розпочався.

Нижче **«Взаємодія»** і **«Кинути»** означають твої поточні ігрові кнопки. Клавіші в цьому виправленні не змінювалися. Оцінюй руки обох гравців у їхніх власних вікнах: приховування іншого гравця через timeline саме по собі не означає поломку ownership.

## 1. Звичайне підняття й кидання

1. А з порожньою рукою піднімає П1.
2. А проходить кілька кроків, повертає камеру, кидає П1.
3. А знову піднімає П1. Повтори 3 рази.
4. Зроби те саме за Б.

**Пройдено:** предмет займає руку; після drop рука порожня; предмет можна повторно підняти. Рука не залишається «зайнятою невидимим предметом». Наявні правила видимості/held pose збережені.

**Збій:** після першого циклу предмет більше не піднімається, дублюється або без причини переходить іншому гравцеві. Розходження фізики після падіння запиши окремо: для N03/N04 додано [окремий сценарій перевірки](N03_N04_Physics_Placement_UA.md).

## 2. Обмеження «один предмет у руці»

1. А тримає П1 і пробує підняти П2 кілька разів.
2. Не кидаючи П1, А відходить від П2.
3. А кидає П1, після чого піднімає П2.

**Пройдено:** поки рука зайнята, П1 залишається в ній, П2 не зникає і не прикріплюється до А. Після drop П1 підняття П2 працює відразу.

**Збій:** друга спроба витісняє П1, забирає П2 у невидиму руку або блокує всі подальші pickup.

## 3. Основний тест виправлення: двоє беруть один предмет

1. Покладіть П1 на підлогу. Руки А і Б порожні; обидва стоять у звичайній дистанції взаємодії та навелися на П1.
2. На рахунок «три» обидва натискають «Взаємодія» один раз.
3. Визначте, у кого П1 у руці. Назвемо його **власником**, іншого — **другим гравцем**. Хто саме виграє, не важливо.
4. Власник залишається на місці й не кидає предмет. Другий гравець натискає «Кинути» 3 рази.
5. Другий гравець піднімає вільний П2.

**Пройдено:** П1 отримав рівно один гравець. Натискання «Кинути» другого не впливає на П1. Другий може підняти П2: його невдалий запит не залишив руку зайнятою.

**Збій N01:** П1 є у двох руках; він перескакує між ними; другий гравець своїм drop скидає П1 у власника; після відмови другий не може взяти П2.

Повтори 10 разів: частину спроб А натискає трохи раніше, частину — Б. Перед кожною спробою обоє кидають усе, П1 знову лежить у світі. Потім поміняйте, хто створює сесію.

**Важливо:** якщо в кожній спробі запит другого гравця взагалі не встиг відправитися до зникнення target, це перевіряє звичайний UX, але не доводить обробку двох конкуруючих запитів. Для цієї ситуації вже є автоматичний authority-тест; у логах ручної перевірки шукай запис про відмову зайнятому предмету.

## 4. Звичайна передача через підлогу

1. А піднімає П1, кидає, Б піднімає П1.
2. Поки Б тримає П1, А натискає «Кинути».
3. Б кидає П1, А знову піднімає.
4. Повтори кілька разів в обидва боки.

**Пройдено:** після кожного drop предмет доступний новому власнику; попередній власник ним більше не керує. Руки обох гравців лишаються працездатними.

## 5. Невдала взаємодія не блокує руку

1. З порожньою рукою натисни «Взаємодія» в порожнечу, на декорацію та на предмет, який за правилами не можна зараз підняти.
2. Після кожної відмови підніми доступний П1.
3. Повтори за клієнта.

**Пройдено:** неправильна ціль нічого не забирає в руку; наступний нормальний pickup працює. Якщо предмет іншої лінії невидимий і на нього не можна навестися, це нормальне обмеження, не причина штучно змінювати gameplay.

## 6. Годинник і стілець із зайнятою рукою

1. Тримаючи П1, взаємодій із доступним годинником.
2. Переконайся, що годинник виконав свою звичайну дію, а П1 залишився у руці.
3. Після штатного розблокування ритуальних стільців, тримаючи П1, сядь на вільний доступний стілець і встань звичайним способом.
4. Кинь П1 та підніми знову. Повтори за Б.

**Пройдено:** годинник/стілець не займають слот предмета й не втрачають свою взаємодію через зайняту руку; після них П1 можна кинути й підняти.

Якщо стілець ще заблокований прогресом ритуалу або зайнятий, відмова очікувана. Не зараховуй її як збій N01.

## 7. Передача через дзеркало

1. Використай ту саму пару дзеркал, предмет і послідовність дій, якими передача працювала до виправлення. Виконай звичайні умови цієї механіки.
2. А тримає дозволений для передачі предмет; рука Б порожня. Передай його через дзеркало.
3. Переконайся: у А рука порожня, у Б предмет. А натискає «Кинути» — у Б нічого не змінюється.
4. Б кидає/знову піднімає предмет або передає назад штатним способом.
5. Якщо твій сценарій дозволяє передавати прямо в руку, повтори з уже зайнятою рукою отримувача.

**Пройдено:** дозволена передача працює як раніше, немає подвійного власника; зайнята рука отримувача не витісняє його попередній предмет. Якщо передача має іншу штатну відмову/fallback, звіряйся з її попередньою поведінкою.

**Збій:** нова перевірка pickup помилково блокує штатну передачу, предмет губиться між гравцями або попередній власник може його скинути.

## 8. Ключ і руна: звільнення руки після використання

1. Підніми правильний ключ і штатно відкрий відповідний замок.
2. Якщо ключ за цим сценарієм витрачається, відразу підніми інший доступний предмет.
3. Підніми руну, встанови її у правильний доступний slot пентаграми, після цього підніми інший предмет.

**Пройдено для N01:** використаний/установлений предмет не залишається у руці, новий pickup працює. Попередні правила правильного ключа/руни збережені.

Падіння або неправильне положення встановленої руни на іншому клієнті може належати до N04. Зафіксуй окремо; саме по собі це ще не доводить регресію N01.

## 9. Повторення із затримкою

Після успіху без затримки повтори тести 3 і 4 зі штатною емуляцією мережі Unreal: помірна latency (цільовий діапазон 100–200 ms) та невелика втрата пакетів. Запиши фактичні обрані налаштування й до якої сторони вони застосовані. Затримка може бути односторонньою або RTT залежно від інструмента, не змішуй ці значення.

**Пройдено:** допускається коротке очікування відповіді сервера, але після її отримання П1 має одного власника, а друга рука не заблокована. Відхилений гравець не може скинути чужий предмет.

Після тесту вимкни емуляцію. Якщо немає другого тестера чи можливості незалежного одночасного керування, познач цей тест «не виконано».

## Як записати результат

Не потрібно повертатися на старий код, щоб перевірити, чи збережена звичайна поведінка. Спочатку пройди цей checklist на новій версії. Якщо відмінність сумнівна, порівняння зі старою збіркою роби окремо, з тим самим content і сценарієм; не змішуй старий `.exe` з новими assets.

| ID | Перевірка | Результат: пройдено / збій / не виконано | Примітка |
| --- | --- | --- | --- |
| 1 | Звичайний pickup/drop за А і Б | | |
| 2 | Зайнята рука, pickup після звільнення | | |
| 3 | Конкуруючий pickup + drop другого гравця | | |
| 4 | Передача через підлогу | | |
| 5 | Pickup після невдалої взаємодії | | |
| 6 | Годинник і розблокований стілець | | |
| 7 | Дзеркальна передача | | |
| 8 | Ключ/руна звільняють руку | | |
| 9 | Конкуренція із latency/loss | | |

При збої запиши: номер тесту, назву предмета, хто host, timelines А/Б, що було в руках до дії, порядок натискань, очікуваний і фактичний результат. Коротке відео обох вікон і логи обох процесів допоможуть відрізнити ownership від visibility/physics.

У серверному Output Log корисні рядки:

```text
[Item] Pickup rejected for ...: ... is already held or reserved by ...
[Item] Drop ignored for ...: no valid owned item
```

Для другого рядка порожня рука — нормальний випадок. Перший підтверджує, що сервер отримав і відхилив pickup зайнятого предмета. Відсутність цих рядків не означає автоматично збій: запит міг зупинитися локальним trace.

Тест навмисно пошкодженого `CurrentHeldItem` не потрібно відтворювати вручну: його вже покриває [автоматична перевірка](PickupOwnership_Test_UA.md).
